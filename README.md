# vendor_data：数据商数据预处理（Bloomberg / Refinitiv / 以后的其它数据商）

本文件：项目总览、工作要求、环境约束、仓库结构。所有子目录通用。
当前进度见 PROGRESS.md；各数据源的处理规则与流程见各目录下的 PROCESSING.md。
最后更新：2026-11-13

## 1. 项目目标

- 把各数据商的原始数据清洗后存进公司内部 xdata。目前有 Bloomberg（部分数据）和 Refinitiv（部分数据），都是历史数据；以后可能补充近期数据，也可能接入其它数据商（每个数据商一个目录）。
- 数据里不只有股票，还有权证等其它证券类型。我自己不用这些，但别人以后可能会用。
- 每个数据商分两个阶段处理，先只做第一阶段：
  - 第一阶段：基本清洗入库（通用，给所有人用）。 原始数据 → xdata。不做任何筛选、不做股票池（univ），保留所有证券类型和所有原始数据。只做字段校验、类型确定与强制转换、重复处理。不能把任何个人用途的偏好写进第一阶段。
  - 第二阶段：按用途筛选。 我的用途是可在美国交易所交易的普通股：确定股票池，处理数据内容层面的异常。第二阶段的代码和说明放在哪个目录，开始做时再定。
- 两份数据的第一阶段都完成后，把 Bloomberg 与 Refinitiv 的证券标识（symbol）对应起来。

## 3. 工作要求（必须遵守）

1. **不推断、不猜测，要实证。** 所有结论必须来自实际数据或原始文档。确认不了的，要明确说"确认不了"，并告诉我去哪里找（哪个网站、哪个文档、Bloomberg 终端的哪个功能），我去取来。
2. **一步一步来。** 每次只让我做一件事，不同时开多条线。
3. **过程可追溯。** 每个处理步骤的原因、依据、流程都要写清楚，以便以后查询：写进对应目录的 PROCESSING.md，代码注释里也写明依据和日期。
4. **新数据入库前必须校验。** 近期数据补充时，要先确认是否符合现有规则（字段名、字段类型、取值范围等）才能入库。
5. **数据量很大。** 代码要考虑内存和 CPU 效率；测试阶段可以先用小部分数据；需要数据基本信息时先让我查看。我一次至少可以用 40 个 CPU 并发。
6. **需要额外信息时，告诉我去哪里找。** 任何时候建议开新对话（Claude 或 GLM）都直接说。
7. **修改了已生成的文件，要明确告诉我改了哪个文件。** 同步方式：我在每次开新对话之前，把 Claude 打包好的整个仓库 zip 下载下来，一次性更新到内网 git。所以：平时改的文档、代码先在 Claude 这边累积；如果需要我提前替换内网的文件，Claude 必须额外明确告诉我。
8. **凡是会改动原始值的处理**（如把某类值视为缺失、置空、截断），必须先征得我确认再实施。确认后作为正式规则写进对应目录 PROCESSING.md 的"改动原始值的规则"一节。
9. **每完成一步都要更新 PROGRESS.md**：做到哪了、结果是什么、下一步是什么。
10. **第一阶段的输出是通用的**：保留所有证券类型（股票、权证等），别人以后可能会用；我个人的筛选需求只放在第二阶段。
11. **外部信息来源必须留存并登记。** 凡是为了确认某件事，需要我去 Bloomberg 终端、数据商网站、客服等外部来源获取的信息，Claude 要提醒我：把原始材料放进 references/ 下；在 SOURCES.md 里登记来源。PROCESSING.md 里引用时写上 SOURCES.md 的编号。
12. **主动提醒开新对话。** Claude 要在合适的时机提醒我开新对话，并说明原因（对话过长、完成大步骤）。提醒前确保文档更新好并打包。
13. **模型与 effort。** 默认使用 Claude Opus 5.5，effort 用 Medium。换模型只在开新对话时做，对话中途只调 effort。每步给出档位建议。
14. **代码要有进度日志，能看出跑到哪了。** 新写或修改的脚本用 Python logging：同时输出到终端和 logs/ 下，带时间戳；记录参数、阶段用时、内存峰值等。
15. **正式写入 xdata 之前，我先自己读代码确认。** 试跑可以直接跑；正式 build / update 要等我读完代码、确认没问题再跑。
16. **严格校验，拒绝静默失败（Fail Fast）。** 不能为了让程序跑完就悄悄放过一些不符合预期的东西。如果在数据流转、读取或写入的过程中，发现了不在预设规则（如 schema）中的列、类型或无法解析的值，必须直接报错并中断，绝不能悄悄跳过（pass）或用默认值填充（正常的业务容错除外，如新数据缺列补空、空值占位符清洗）。程序“跑完了”不等于“跑对了”，任何异常都必须暴露在阳光下，由人工决定是修改规则还是清洗数据。

语言 | Python（我的 Python 比 C++ 熟练得多）

### 使用 GLM 的规则
- 给 GLM 的指令必须明确要求它只从原文中摘取，不允许推断、补充或解释；原文里找不到就写"原文未提及"。
- 指令太长时写成 .md，在对话里让 GLM 去读。
- GLM 有上下文限制，需要适时开新对话。
- GLM 的输出 Claude 无法核对，关键结论以脚本输出或原文为准。

## 5. 开新的 Claude 对话时
上传：本文件、PROGRESS.md、当前在做的那个目录下的 PROCESSING.md 和全部 .py（做 Bloomberg 时还要加上 common/README.md）。然后告诉它："按 PROGRESS.md 的'下一步'继续。"
