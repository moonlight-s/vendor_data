# vendor_data：数据商数据预处理（Bloomberg / Refinitiv / 以后的其它数据商）

> 本文件：项目总览、工作要求、环境约束、仓库结构。所有子目录通用。
> 当前进度见 [`PROGRESS.md`](PROGRESS.md)；各数据源的处理规则与流程见各目录下的 `PROCESSING.md`。
> 最后更新：2026-11-11

---

## 1. 项目目标

- 把各数据商的原始数据清洗后存进公司内部 xdata。目前有 **Bloomberg**（部分数据）和 **Refinitiv**（部分数据），都是历史数据；以后可能补充近期数据，也可能接入**其它数据商**（每个数据商一个目录）。
- 数据里**不只有股票**，还有权证等其它证券类型。我自己不用这些，但别人以后可能会用。
- 每个数据商分两个阶段处理，**先只做第一阶段**：
  1. **第一阶段：基本清洗入库（通用，给所有人用）。** 原始数据 → xdata。不做任何筛选、不做股票池（univ），**保留所有证券类型和所有原始数据**。只做字段校验、类型确定与强制转换、重复处理。**不能把任何个人用途的偏好写进第一阶段。**
  2. **第二阶段：按用途筛选。** 我的用途是**可在美国交易所交易的普通股**：确定股票池，处理数据内容层面的异常。第二阶段的代码和说明放在哪个目录，开始做时再定。
- 两份数据的第一阶段都完成后，把 Bloomberg 与 Refinitiv 的**证券标识（symbol）对应起来**。

## 3. 工作要求（必须遵守）

1. **不推断、不猜测，要实证。** 所有结论必须来自实际数据或原始文档。确认不了的，要明确说"确认不了"，并告诉我去哪里找（哪个网站、哪个文档、Bloomberg 终端的哪个功能），我去取来。
2. **一步一步来。** 每次只让我做一件事，不同时开多条线。
3. **过程可追溯。** 每个处理步骤的原因、依据、流程都要写清楚，以便以后查询：写进对应目录的 `PROCESSING.md`，代码注释里也写明依据和日期。
4. **新数据入库前必须校验。** 近期数据补充时，要先确认是否符合现有规则（字段名、字段类型、取值范围等）才能入库。
5. **数据量很大。** 代码要考虑内存和 CPU 效率；测试阶段可以先用小部分数据；需要数据基本信息时先让我查看。我一次至少可以用 **40 个 CPU** 并发。
6. 需要额外信息时，告诉我去哪里找。**任何时候建议开新对话（Claude 或 GLM）都直接说。**
7. **修改了已生成的文件，要明确告诉我改了哪个文件。** 同步方式：我在每次开新对话之前，把 Claude 打包好的整个仓库 zip 下载下来，一次性更新到内网 git。所以：
    - 平时改的文档、代码先在 Claude 这边累积，不需要我逐个替换；
    - **如果在那之前就需要我替换内网的文件**（比如改了代码、下一条命令要用到新代码），Claude 必须**额外明确告诉我**：替换哪个文件、为什么现在就要替换。
8. **凡是会改动原始值的处理（如把某类值视为缺失、置空、截断），必须先征得我确认再实施。** 确认后作为正式规则写进对应目录 `PROCESSING.md` 的"改动原始值的规则"一节。
9. **每完成一步都要更新 `PROGRESS.md`**：做到哪了、结果是什么、下一步是什么。
10. **第一阶段的输出是通用的**：保留所有证券类型（股票、权证等），别人以后可能会用；我个人的筛选需求只放在第二阶段。
11. **外部信息来源必须留存并登记。** 凡是为了确认某件事，需要我去 Bloomberg 终端、数据商网站、客服等外部来源获取的信息，Claude 要提醒我：
    - 把原始材料（文档、截图、导出文件、客服回复）**放进内网**，放在对应数据商目录的 `references/` 下；
    - 在该目录的 `SOURCES.md` 里**登记来源**：编号、获取日期、来源（具体到网站 URL / 终端功能 / 联系人）、文件名、用来确认什么。
    - `PROCESSING.md` 里引用某个外部依据时，写上 `SOURCES.md` 的编号（如 `[BBG-S01]`）。
12. **主动提醒开新对话。** Claude 要在合适的时机提醒我开新对话，并说明原因。合适的时机包括：
    - 对话已经很长（越长每条回复越耗用量，对早期细节的把握也会变差）；
    - 完成了一个数据集，或完成了 `PROGRESS.md` 路线上的一大步。

    提醒前先确保 `PROGRESS.md` 和相关文档都已更新，**把整个仓库打包成 zip 发给我**（用于更新内网 git，见第 7 条），并告诉我新对话要上传哪些文件、第一条消息说什么。
13. **模型与 effort。** 默认使用 **Claude Opus 5.5，effort 用 Medium**（用量有限，不能一味调高）。
    - **换模型只在开新对话时做。** 同一个对话里中途换模型，新模型要先把整个对话重读一遍，额外耗用量（界面会弹出提示）。需要换模型时，Claude 应建议开新对话，并按第 12 条做好交接。
    - **对话中途只调 effort。** 调 effort 是否也会触发重读，目前未确认；如果调的时候也弹出"要重读整个对话"的提示，就不调。
    - **Claude 在每一步开始前给出具体建议**：调到哪一档、为什么、这一步做完后调回哪一档。不需要调时也明确说"保持 Medium"。参考：

      | 步骤类型 | 建议档位 |
      |---|---|
      | 纯机械：只跑一条命令、看截图、把结果记进文档 | 只有一两条回复时保持 Medium（不值得调）；接下来连续好几步都是机械的，才调到 Low |
      | 常规：解读报告、小改代码、更新文档 | Medium（默认） |
      | 写或大改核心代码；影响全局的设计决定（如主键冲突的选行规则、新数据源的第一阶段方案、symbol 对应规则） | High |
      | 用 High 仍反复出错，或问题特别棘手 | 再高一档 |

      档位名称以界面实际显示为准。
    - 做完需要调高的那一步，提醒我调回 Medium。
    - 开新对话时，如果接下来几步主要是机械操作，Claude 可以建议新对话改用 Sonnet 5.5。
14. **代码要有进度日志，能看出跑到哪了。** 新写或修改的脚本用 Python `logging`：
    - 同时输出到终端和 `logs/{数据集}_{命令}_{时间}.log`（`logs/` 不进 git），每行带时间戳；
    - 记录：开始时的参数和规模（文件数、组数、并发数）；每个阶段的开始、结束和用时；每完成一个任务记一行（第几个 / 共几个、处理了哪些文件、行数、用时、预计剩余时间）；警告和错误；结束时的汇总；
    - 进度按**已完成**的任务计，不按"已派发"的任务计（`tqdm` 包在 joblib 的任务生成器外面时，显示的是派发进度，会提前接近 100%）。
15. **正式写入 xdata 之前，我先自己读代码确认。** 试跑（`--trial`）可以直接跑；正式 `build` / `update` 要等我读完代码、确认没问题再跑。Claude 给出正式入库的命令时，要同时列出这次相对上次我确认过的版本改了哪些函数，方便我审阅。

## 4. 工作环境与约束

| 项目 | 情况 |
|---|---|
| 数据和代码位置 | 公司内网。**只能截图**给 Claude，不能直接传文件 |
| 内网 AI | **GLM 5.3 Flash**，可让它做些工作，再截图给 Claude（规则见下） |
| Bloomberg 数据说明 | 内网某目录下有说明文档；不能直接给 Claude，而且对字段的解释不一定完整 |
| Refinitiv 数据说明 | 有一定的说明文档；同样不能直接给 Claude，也不一定完整 |
| Bloomberg 终端 | 有，可查字段定义（`FLDS <GO>`），可问客服（`HELP HELP`） |
| 内部存储 | xdata（`from xdata.client import get_client`），接口：`exists / register / write / append / read`。**列式存储**；存储地址同一个，按 `register` 时的 data_type 在底层分块：`daily` 按年存、按年读，`minute` 按月，`second` 按天（可并行写）。详细设定、来源、实测耗时和待确认问题见 [`common/README.md`](common/README.md) |
| 语言 | Python（我的 Python 比 C++ 熟练得多） |

### 使用 GLM 的规则
- 给 GLM 的指令必须**明确要求它只从原文中摘取，不允许推断、补充或解释**；原文里找不到就写"原文未提及"。
- 指令太长时写成 `.md`，在对话里让 GLM 去读。
- GLM 有上下文限制，需要适时开新对话。
- GLM 的输出 Claude 无法核对，关键结论以脚本输出或原文为准。

## 5. 开新的 Claude 对话时

上传：本文件、`PROGRESS.md`、当前在做的那个目录下的 `PROCESSING.md` 和全部 `.py`（做 Bloomberg 时还要加上 `common/README.md`）。然后告诉它："按 `PROGRESS.md` 的'下一步'继续。"
